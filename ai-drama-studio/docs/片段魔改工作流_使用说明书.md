# 片段魔改工作流（video-restyle）使用说明书

> 一句话：**给它一条已经存在的视频，它还你一条"同一条片子，但在另一个世界里重拍了一遍"。**
>
> 典型玩法就是标题里那个问题——"假如龙珠是印度人拍的""假如这条会议室戏是 1985 年邵氏拍的"
> "假如这段 vlog 是维伦纽瓦拍的"。
>
> 工作流文件：`backend/config/workflows/video-restyle.json`
> 风格库：`backend/config/restyle_presets.json`（22 条目标风格）
> 提示词模板：`backend/config/prompts/scripts/restyle_reverse.yaml`、`restyle_bible.yaml`、`restyle_qc_vision.yaml`
>
> 四条线的公共部分（节点类型全表、通道选择、密钥存放、自检清单）在 [WORKFLOW_GUIDE](WORKFLOW_GUIDE.md)，本手册只讲这条线特有的。

---

## 0. 这条线和另外两条线的根本差别

| | AI 动漫（anime-drama） | 真人剧（realistic-drama） | **片段魔改（video-restyle）** |
|---|---|---|---|
| 输入 | 一句创意 | 一句创意 | **一条现成的视频** + 一个目标风格 |
| 谁决定拍什么 | LLM 写剧本 | LLM 写剧本 | **原片**，一个字都不改写 |
| 谁决定构图 | 分镜脚本 LLM | 分镜脚本 LLM | 原片，**明令禁止改** |
| 一致性靠什么 | 画风圣经 + 定妆图 | 摄影规格 + 定妆照入库 | **原片关键帧当改写对象** |
| 音轨 | AI 配音（多角色） | AI 配音（多角色） | **原片音轨垫进去** |
| 有没有台词文本 | 有（剧本） | 有（剧本） | **没有**（视觉模型听不见声音） |

所以这条线的全部工程难点只有一个：**让模型真的去"换世界观"，而不是给原片加个滤镜。**
下面每一处设计（反推铁律、世界观圣经的置换清单、双轴质检、原音轨）都是为了这一件事。

---

## 1. 全链路：7 个节点，产物落在哪

```
input_clip        读入源视频：ffprobe + 抽 4 张关键帧 + 抽出原音轨
   ↓
reverse_prompt    视觉模型看这 4 张帧，逐镜如实记录（人数/站位/动作/机位/道具/文字）
   ↓
style_bible       世界观圣经：把选中的目标风格翻译成"原片 X → 替代品 Y"的替换清单
   ↓
shot_images       逐镜重绘：第 i 镜拿第 i 张源帧当被改写的对象 + 双轴质检打分
   ↓
shot_videos       图生视频：以重绘出来的图为第一帧，只补一个动作
   ↓
video_edit       （出厂关闭）整段改风格的替代路线，见第 6 节
   ↓
final_cut         拼接 + 垫原片音轨（默认不循环）
```

产物目录（后端 `output/` 已挂在 `/media/output` 下）：

| 节点 | 落盘位置 |
|---|---|
| `input_clip` | `backend/output/video-restyle/input_clip/frames/frame_01_0.0s.jpg`（文件名带秒数）、`…/input_clip/source_audio.m4a`；配了 `clip_seconds` 才有 `…/input_clip/clip_01.mp4` |
| `reverse_prompt` | 不落盘，只进 checkpoint（`runs/<run_id>.json`） |
| `shot_images` | `backend/output/video-restyle/shot_images/shot_images_000.png` … |
| `shot_videos` | `backend/output/video-restyle/shot_videos/shot_videos_000.mp4` … |
| `final_cut` | `backend/output/video-restyle/restyle_final.mp4` |

## 2. 跑之前必须满足的四件事

1. **ffmpeg / ffprobe 在 PATH 上**（或 `.env` 里写 `FFMPEG_BIN` / `FFPROBE_BIN` 指到绝对路径）。
   抽帧、抽音轨、切片、合成全依赖它。缺它时 `input_clip` 会直接抛出中文提示，不会静默出废片。
   > 本仓库作者这台机器**没有**装 ffmpeg，所以第 1、7、8 节的实跑路径未在本机验证过；
   > 引擎逻辑是靠离线自检（`scripts/test_video_input.py`，51 项）验证的。
2. **一个能看图的语言模型**：`reverse_prompt` 和质检都走 `vision_completion`。
   取值顺序是 `VISION_API_KEY`（配 `VISION_BASE_URL` / `VISION_MODEL`，默认 `gpt-4o-mini`）
   → `ZHIPU_API_KEY`（默认 `glm-4v-flash`，免费档）→ **退回普通 LLM 配置**。
   ⚠️ 第三级兜底意味着：只配了 DeepSeek 时它会拿 `deepseek-chat` 去尝试收图，
   多半直接报错或瞎编。这条线请务必给前两级之一。
3. **源视频要能落到本机**：只支持"从素材库取"（`/make` 页面上传，或 `POST /api/assets/upload`
   之后把返回的 `id` 填进 `source_video`）。**网络直链不支持**——要先落地才能 ffprobe 和抽帧，
   报错信息里会这么写。上传接口需要 `python-multipart`（在 `requirements.txt` 里，
   `pip install -r requirements.txt` 装全）。
4. **生图 + 生视频通道**：跟着全局配置走（`GET /api/system/providers` 看当前挑到谁）。
   出厂 `shot_videos` 写死 `provider: seedance`，因为它的参考图走 base64，**不需要公网隧道**。

## 3. `input_clip`：把一条视频读进流水线

它是这条线的入口，也是引擎里唯一一个**不生产内容**的节点类型（`video_input`）。

| 字段 | 默认 | 作用 |
|---|---|---|
| `source` | 空 | 素材库 asset id / `/media/assets/xxx` 链接 / 绝对路径 / 相对 backend 的路径。**留空时引擎自动取运行输入里的 `source_video`**，所以工作流 JSON 里故意不写这个键——写了 `{{source_video}}` 反而会在没传视频时把大括号原样当路径去找 |
| `frames` | 4 | 抽几帧（均匀取样，取的是每段的中点而不是端点，因为端点经常是黑场） |
| `frame_times` | 无 | `[0.5, 7.2]` 精确指定秒数，写了就不均匀抽 |
| `max_side` | 1024 | 帧的最长边，压小一点给视觉模型看够用，还省 token |
| `extract_audio` | true | 顺手抽出原音轨给成片用 |
| `clip_seconds` | 无 | 按 N 秒切成片段。**切片会顶掉源视频**：下游按"视频"取时拿到的是片段数组，正好一镜改一段 |

产物形状有个**坑必须知道**：它的 payload **刻意不带 `paths` 键**。
因为里面同时装着 `.mp4` 和 `.jpg`，而引擎收集媒体时先看 `paths`——留着它就会把视频文件
当参考图喂给生图模型。所以下游必须按用途选对键：

- 要帧 → `images` / `frames`（`init_image_from`、`images_from` 走的就是这条）
- 要视频 → `videos` / `clips`（`source_video_from` 走这条）
- 要音轨 → `audios`（`bgm_from` 走这条）

## 4. `reverse_prompt`：先看清原片，再谈改

节点上写 `"images_from": "input_clip"`，`llm` 节点就会改走多模态通道：把关键帧（**最多 4 张**）
连同模板一起交给视觉模型。这也决定了这条线的一次产量：**反推只会为它看见的那 4 张帧出镜头**。
想让一条片子出 8 镜，得同时改两处（`input_clip.frames` 与取帧上限），详见第 9 节的聊天说法。

模板里那 8 条"观察铁律"是这条线的地基，最关键的三条：

- **只写看见的**，看不清就写"看不清"。把"换成印度版"和"描述原片"塞进同一个提示词，
  模型会跳过观察、直接编一个它想象中的原片——出来东西和源视频毫无关系，这是本线最常见的失败。
- **每一镜必须写清人数、站位、朝向、一个动作**。下游要按这个构图重画，写错等于换了一条片子。
- **props 逐项列、可读文字逐条抄**。魔改的本质就是替换 props 和文字，列不出来就没得换。

输出 schema（每个 shot 一项）：

```
source_logline / source_style / source_era_region
people[] {id, appearance, position}
replaceable_text[]
shots[] {index, time, location, subject, blocking, action, camera, lighting,
         color, wardrobe, props[], background, compose_note, dialogue_hint,
         image_prompt, video_prompt}
audio_note / what_makes_it_what_it_is[]
```

最后两栏是给机器用的：`image_prompt` 是**英文 25-40 词、只写看得见的东西、不带风格词**
（风格由 `style_bible` 拼进来，两边不抢话）；`video_prompt` 是**英文 15-25 词、一个动作加一个
镜头运动**，动作必须是原片已经有的那个。

## 5. `style_bible`：把"印度风"翻译成能执行的清单

这一步的存在理由：预设库里的中文风格词直接拼到生图提示词上，只会得到"同一条片子加了个滤镜"。
世界观是靠道具、服装、招牌文字、光源和建筑撑起来的，必须**逐条**把原片里真实存在的东西换成替代品。

它的输入 = 上一步的如实记录 + 目标风格预设的 8 个扁平字段（`preset_label`、`preset_era_region`、
`preset_signature`、`preset_positive`、`preset_style_token`、`preset_camera`、`preset_audio`、
`preset_displacement`）。这几个键由 `/make` 页面从风格库里摊平传进来；手跑 curl 时也要自己传。

输出是一份"这一条片子的置换方案"：

```
target_label / style_token(英文 40-70 词) / style_cn / negative_prompt(英文 12-20 项)
world_rules[] / props_map[{original,replacement,why}] / wardrobe / set_design
lighting / palette / text_plan / camera_rules[] / must_keep[] / audio_plan
funny_lever / risk
```

铁律里最有用的两条：

- **认得出测试**：把颜色全抽掉，只看道具、服装、建筑、招牌文字、车辆、植被，
  观众仍然要能立刻说出"这是宝莱坞"。达不到就是没换成功。
- **禁止改的东西要显式列出来**（`must_keep`）：构图、机位、景别、人物数量与站位、动作、镜头长度。
  模型重画时会顺手改这些，一旦改了就不是魔改，是重拍。

## 6. 两种改法：出厂路线 vs 整段编辑

### 6.1 出厂路线：逐镜重绘 + 图生视频（`shot_images` → `shot_videos`）

```json
"shot_images": {
  "type": "image", "foreach": "reverse_prompt.shots",
  "init_image_from": "input_clip",
  "prompt": "{{style_bible.style_token}}, {{image_prompt}}, lighting: …, keep the reference
             frame's exact composition … — replace only wardrobe, props, signage text,
             set dressing, vehicles, vegetation and light",
  "qc": {"enabled": true, "threshold": 8, "max_attempts": 2,
         "compare_source": true, "prompt_template": "restyle_qc_vision.yaml"}
}
```

- `init_image_from`（本线新增的引擎字段）和 `images_from` 的区别：后者是把上游所有图一次性
  全挂上，前者是**第 i 镜只拿第 i 张**——"这一镜对应源视频的哪一帧"。配对越界时不报错，
  只发一条进度提示"这一镜只能按文字重画"。
- `compare_source: true` 让质检同时看见两张图：第 1 张=重绘结果，第 2 张=原片对应帧。
  没有它，模型无从判断"构图有没有被改"。

质检是**双轴**的，这是本线和另外两条线最大的不同：只看"像不像目标风格"会放过"只加了滤镜"；
只看"贴不贴原片"会把魔改变成复刻。五项各 0-2 分、满分 10：

| # | 项 | 判什么 |
|---|---|---|
| 1 | `world_swapped` | 遮住颜色只看服装道具陈设文字光源，认不认得出目标世界 |
| 2 | `composition_kept` | 人物数量/位置/朝向/景别/机位高度是否与原片一致 |
| 3 | `no_leftover` | 有没有原片残留（不属于目标世界的物件、文字、车型、建筑、植被） |
| 4 | `legible_image` | 手指肢体正常、脸不融化、文字不乱码、无二次压缩糊边 |
| 5 | `on_model` | 质感是否落在目标风格的摄影逻辑上 |

**第 1 项或第 2 项为 0 分时总分封顶 4 分**；阈值 8 分以下按 `rewrite_prompt`（一句英文、只加约束
不改主题、≤45 词）重画，最多 2 次。

### 6.2 替代路线：整段视频编辑（`video_edit` 节点，出厂 disabled）

不重绘关键帧、不重新生成运动，而是把**整段源视频**直接交给支持视频编辑的模型改画风。
好处是运动与时长百分百保留；代价是目前只有少数通道支持，且要公网可达的源视频。

```json
"video_edit": {
  "type": "video", "disabled": true,
  "provider": "dashscope", "model": "wan2.7-videoedit", "mode": "video_edit",
  "source_video_from": "input_clip", "first_frame_from": "shot_images"
}
```

- `source_video_from`（本线新增的引擎字段）：按下标取上游 `video_input` 的切片，
  没有 foreach 时取整段。**本地路径会先经 `PUBLIC_ASSET_BASE_URL` 发布成公网 URL**
  再交给云端；`provider: comfyui` 时保持本地路径（它和后端在同一台机器上）。
- 缺源视频 / 源视频是本机文件时，报错会点名要你填哪个键、去哪配，不会静默退化成文生视频。
- `first_frame_from` 在这条路上不是首帧，而是作为 `reference_image` 一起送进去当风格参考。
- ⚠️ **打开它之后必须把 `final_cut` 的 `from` 改成 `["video_edit"]`**，否则成片里还是旧的
  `shot_videos`。用聊天说一句就行（见第 9 节）。
- 想走本地：导出一个 VACE 一类"视频进视频出"的 ComfyUI 预设
  （`scripts/make_comfyui_preset.py`，用法见《真人剧工作流_使用说明书》第 5.2 节），
  然后 `provider: comfyui` + `workflow_file: 你的预设.json`。

### 6.3 成片：原片音轨垫底

```json
"final_cut": {"from": ["shot_videos"], "bgm_from": "input_clip", "bgm_gain_db": -2}
```

`bgm_gain_db: -2` 而不是默认音乐的那种 -22dB：这里垫的是**原台词**，压低就没意思了。
另一个自动行为：走 `bgm_from` 时 `bgm_loop` 默认 `false`（自己指定的 BGM 仍然循环铺满）。
原因很实际——重绘后的成片通常比源视频长，循环会把台词播第二遍，比没音轨更难听。

## 7. 目标风格库：22 条"假如这条片子是 ___ 拍的"

`backend/config/restyle_presets.json`，按四类分：

| 类别 | 条目 |
|---|---|
| 地域 | `bollywood` 宝莱坞歌舞片、`nollywood` 尼日利亚诺莱坞、`k-cinema` 韩国电影、`j-morning` 是枝裕和式日剧晨间、`soviet` 苏联译制片、`hk80s` 八十年代港片、`shaw` 邵氏黄梅调、`telenovela` 拉美容光剧、`wuxia-cctv90` 九十年代央视武侠、`zhang-yimou` 张艺谋式色彩、`nordic-noir` 北欧黑色、`wildwest` 意式西部片 |
| 时代 | `vhs` 九十年代家用录像带、`propaganda-cartoon` 老宣传片动画 |
| 媒介/导演 | `anderson` 韦斯·安德森、`kurosawa` 黑泽明、`nolan` 诺兰、`wong` 王家卫、`tarantino` 塔伦蒂诺、`lynch` 林奇、`scifi-neon` 维伦纽瓦式科幻 |
| 讲座 | `anime-live` "假如这部动画被真人拍出来" |

每条 13 个字段：`id, label, category, alias[], era_region, signature, positive, style_token,
negative, displacement[], camera, audio, best_for`。
其中 `/make` 会把 `label/era_region/signature/positive/style_token/camera/audio/displacement`
八项摊平成 `preset_*` 传进运行输入。

**加一条自己的风格**：直接往 `presets` 数组里追加一条同样 13 键的对象，存盘即生效
（接口 `GET /api/system/restyle_presets` 每次现读文件，不用重启）。写的时候守住两个要求：
`style_token` 只写摄影与美术（介质/镜头/光圈/布光/调色/质感/陈设），**不许出现 8k、
ultra detailed 这类画质词**；`displacement` 每条都是"原片 X → 替代品 Y"的具体落点，
不写"更印度风"这种没有着落的空话。

## 8. 怎么跑

### 8.1 页面（推荐）

`/make` → ① 选**片段魔改（换世界观）** → ② 写一句"这条素材拍的是什么"（会喂给反推节点当对齐信息）
→ 上传源视频（进素材库）→ 选目标风格（下面会展开它的"一眼可辨 / 替换清单 / 适合 / 音轨"四行说明）
→ ③ 选画幅（**横屏素材一定选横屏**，它同时决定重绘尺寸和成片尺寸）→ 开始生成。

这条线的"④ 镜头数"位置换成了说明文字：镜数由抽帧数决定，不是滑块。
高级选项里的"AI 配音"对本线无效（没有配音节点），字幕也建议关掉——原片台词在音轨里。

### 8.2 命令行

> 端口按你实际起的改：默认 8000，而本仓库 `frontend/.env.local` 把后端指到了 8013。

```bash
# 1) 上传源视频，拿 asset id
curl -F file=@D:/clips/dragon-ball.mp4 -F tags=restyle-source \
     http://127.0.0.1:8000/api/assets/upload

# 2) 看有哪些目标风格（本地文件，不联网）
curl http://127.0.0.1:8000/api/system/restyle_presets

# 3) 起一条运行：preset 的字段必须摊平成 preset_*，键名要和 restyle_bible.yaml 里的一致
curl -X POST http://127.0.0.1:8000/api/runs/ -H 'Content-Type: application/json' -d '{
  "workflow": "video-restyle",
  "input": {
    "title": "四个人在会议室吵架，最后有人摔门",
    "source_video": "把上一步返回的 id 填这里",
    "preset_label": "宝莱坞歌舞片",
    "preset_era_region": "北印度，排灯节前后的集市色彩",
    "preset_signature": "饱和的红黄绿、群体舞蹈、wind-machine 头发、说唱式构图",
    "preset_positive": "高饱和暖色调，群体群舞构图，纱丽与库尔塔",
    "preset_style_token": "shot on anamorphic 2.35:1, saturated marigold reds and turquoise, gold bounce-board highlights",
    "preset_camera": "英雄登场用低角度仰拍，对话用过肩急推，群舞用大远景",
    "preset_audio": "保留原台词节奏但换印度语种口型感，环境声加集市与塔布拉",
    "preset_displacement": ["玻璃会议室 → 殖民风格拱廊会议室", "轿车 → 装饰花环的 Ambassador 出租车"]
  },
  "overrides": {"shot_images": {"width": 768, "height": 1344, "preview_gate": 2}}
}'
```

## 9. 用 AI 聊天改这一步

任意工作流页（`/pipeline`）选中节点后右键"AI 改这一步"，或直接对助手说。下面是本线最常用的说法：

| 你想要什么 | 说这句 |
|---|---|
| 一条片子出 8 镜 | 「把 input_clip 的 frames 改成 8，并让 reverse_prompt 一次看 8 张关键帧」 |
| 源视频是横屏 | 「把 shot_images 的 width height 改成 1344x768，final_cut 改成 1280x720」 |
| 换目标风格但保留这条片子 | 「把运行输入里的 preset 换成 kurosawa」／「按黑泽明的低机位与强对比重新出 world_rules」 |
| 老被判"没换干净" | 「restyle_qc_vision 的第 3 项 no_leftover 加一条：只要出现现代塑料椅、玻璃幕墙、英文 logo 就直接给 0」 |
| 重画时构图老跑 | 「把 style_bible 的 must_keep 里加一句'左右两侧人物的相对位置不得交换'」并在 shot_images 提示词末尾加上它 |
| 不想让质检重画太多次烧钱 | 「shot_images 的 qc.max_attempts 改成 1」 |
| 走整段编辑那条路 | 「打开 video_edit 节点，并把 final_cut 的 from 改成只引用 video_edit」 |
| 源视频只改中间 12 秒 | 「input_clip 加 clip_seconds=3，并只反推前 4 个切片」 |
| 换更便宜的通道 | 「shot_videos 的 provider 改成 zhipu，model 用免费的 cogvideox-flash」 |
| 不要原片音轨 | 「把 final_cut 的 bgm_from 去掉」 |

改完记得**保存工作流**（页面顶部），否则 `/pipeline` 上"运行"用的还是磁盘上的旧版本；
`/make` 永远读磁盘版本，看不到你未保存的改动。

## 10. 成本开关（本线一次运行的花费在哪）

| 项 | 出厂值 | 想省钱怎么调 |
|---|---|---|
| 反推 | 1 次视觉调用，4 张帧，`max_tokens: 6000` | 帧数就是成本；`frames: 3` 能省一档 |
| 世界观圣经 | 1 次文本调用 | 固定 1 次，无所谓 |
| 重绘 | 每镜 1 次生图 ×（1 + 最多 2 次质检重画）+ 质检视觉调用 | `preview_gate: 2` 先选优；`qc.max_attempts: 1`；`qc.enabled: false` 最省 |
| 生视频 | 每镜 1 段 × `seconds` | 竖屏 720p、每镜 3-5 秒先验证观感 |
| 整段编辑 | 默认关 | 打开后按秒计费，且**输入视频时长也计入**，先 `clip_seconds` 切短 |

## 11. 排错

| 现象 | 原因与解法 |
|---|---|
| `input_clip` 直接失败：找不到 ffmpeg、ffprobe | 装 ffmpeg 或在 `.env` 写 `FFMPEG_BIN` / `FFPROBE_BIN` 绝对路径 |
| 报"没有给源视频" | 运行输入没带 `source_video`（`/make` 页面没上传源视频就点了开始） |
| 报"源视频暂不支持直链" | 传了 `http(s)` 地址。先 `POST /api/assets/upload`，用返回的 id |
| 报"找不到源视频：…（试过 …）" | 素材库里没有这个 id / 文件名。`/make` 重传一次最省事 |
| `reverse_prompt` 抛"要『看图说话』但上游没有可用图片产物" | `input_clip` 没抽到帧：多半是 ffmpeg 缺失或源视频损坏 |
| 反推出来的内容和画面无关 | 视觉通道退回了纯文本模型（只配了 DeepSeek）。给 `VISION_API_KEY` 或 `ZHIPU_API_KEY` |
| 提示词里留下原样的 `{{…}}` | 引用了没挂 `depends_on` 的上游。引擎只把**直接上游**放进渲染上下文——让 AI「把 X 挂到 Y 的 depends_on 上」 |
| 每一镜都拿同一张源帧 | 该节点没在 foreach 上（`init_image_from` 按下标配对，没有 index 就退回第一张） |
| 质检分数一直 8 分以下反复重画 | 目标世界与原片差异太小（预设选错）或 `world_rules` 太虚。看 `logs` 里的 `issues`，改 `style_bible` 而不是改阈值 |
| 成片有黑边 | 画幅没跟源视频一致：③ 选横屏/竖屏，或让 AI 改 `final_cut.fit`（`contain` 留边、`cover` 裁切） |
| 听见台词重播 | 关掉 `bgm_from`，或让 `seconds × 镜数 ≈ 源视频时长` |
| `video_edit` 报"只能读公网视频 URL" | 没配 `PUBLIC_ASSET_BASE_URL`（ngrok / cloudflared 隧道）。不想开隧道就改 `provider: comfyui` + 本地 VACE 预设 |

## 13. 已知限制（诚实清单）

1. **镜数 = 抽帧数，上限 4**。`images_from` 与 `vision_completion` 都硬顶 4 张图，
   所以想让一条片子出 6-8 镜要改两处代码而不只是改配置。当前设计取舍：4 镜足以验证一条素材的观感。
2. **没有台词/字幕层**。视觉模型听不见声音，这条线拿不到原片对白文本，
   所以不做重配音、不做字幕对齐。要改台词得先接 ASR（未实现）。
3. **原片音轨是整段铺底，不与逐镜对齐**。画面是逐镜重绘的，声音是一整条，
   长于源视频时后段静音（默认不循环）。要严格一镜一镜配，得让 `clip_seconds` 切片与
   逐镜音频一起走另一条链路。
4. **本线整体未在本机实跑过**：作者这台机器没有 ffmpeg，也没有 `python-multipart`
   （上传接口起不来）。引擎逻辑与请求体形状由离线自检覆盖，端到端效果需要你在装好依赖的机器上验证。
5. **`video_edit` 依赖上游模型能力**。`wan2.7-videoedit` 的请求体形状是从已核对的参考实现
   （Pixelle-Video 的 DashScope 封装）移植的，本仓库未持有权重、未实跑验证；
   失败时先按第 11 节最后一条排查公网可达性。
6. **构图保持依赖模型**。重绘路线下，`init_image` 参考帧 + `must_keep` 提示词只是强约束，
   不是硬锁。质检会把"构图被改"判成 0 分封顶，但兜不住所有情况——要求严格就用 `video_edit` 路线。
7. **`/make` 对本线只覆盖默认参数**：帧数、每镜秒数、质检阈值这些都得去工作流页改（或用聊天）。
