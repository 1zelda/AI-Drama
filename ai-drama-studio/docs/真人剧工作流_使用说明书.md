# 真人剧（写实电影感）工作流 · 使用说明书

> 适用工作流：`realistic-drama`（`ai-drama-studio/backend/config/workflows/realistic-drama.json`）
> 版本：1.0.0 ｜ 编写日期：2026-09-24
> 四条线的公共部分（节点类型全表、通道选择、密钥存放、自检清单）在 [WORKFLOW_GUIDE](WORKFLOW_GUIDE.md)，本手册只讲这条线特有的。

这条线要解决的不是「画得好看」，是**看起来像真人拿摄影机拍的**。动漫线（`anime-drama`）
可以靠画风遮丑——笔触、色块、描线都是"这是画"的免责声明；写实线没有这层保护，
皮肤一磨皮、光一平、手指一多，观众立刻判定为 AI。所以这条线的六个模板全部围绕
**「越追求完美越假」**这一条来写，并且带来三个动漫线没有的能力：

1. **摄影规格圣经**：全剧的媒介/镜头/光圈/布光/调色/质感只决定一次，逐字拼进每张图，
   并且专门有一个反磨皮的质检环节；
2. **定妆照自动回填角色档案库**：选角出的图直接变成后续每一镜的参考图，不需要手动登记；
3. **按说话人分音色**：三个人三个嗓子，旁白单独一路，甚至可以一镜一个克隆音色。

## 1. 先看流程图

```
一句创意（title / genre / duration / style / shots）
   │
   ├─① script_planner        llm    real_script.yaml      → 对白驱动的短剧剧本（节拍+台词+沉默戏）
   ├─② style_bible           llm    real_style.yaml       → 摄影规格六项 + 反向清单            ← 全剧只定这一次
   ├─③ character_generator   llm    real_characters.yaml  → 选角卡：不完美特征 + edge-tts 音色
   ├─④ character_assets      image  foreach 角色           → 定妆照 →【自动写进角色档案库】
   ├─⑤ scene_generator       llm    real_scenes.yaml      → 实景卡：光源 + 磨损 + 道具
   ├─⑥ scene_assets          image  foreach 场景           → 空镜（无人、无可读文字）
   ├─⑦ storyboard_generator  llm    real_storyboard.yaml  → 分镜：line/speaker/subtitle/shot_type
   ├─⑧ shot_images           image  foreach 镜头 + 质检    → 每一镜首帧（带参考图，反塑料脸质检）
   ├─⑨ shot_end_frames       image  foreach 镜头 【默认关】 → 尾帧（要换支持首尾帧的 provider）
   ├─⑩ narration             tts    foreach 镜头           → 按说话人分音色配音
   ├─⑪ shot_videos           video  foreach 镜头           → 图生视频
   ├─⑫ lipsync               comfyui_video 【默认关】       → 逐镜口型同步（吃 ⑩ 的配音）
   └─⑬ final_cut             postprocess                  → 归一化+烧字幕+垫配音+片头片尾 → final.mp4
```

产物落盘位置：

| 内容 | 路径 |
|---|---|
| 图片 / 视频 / 音频 | `backend/output/realistic-drama/<节点id>/` |
| 定妆照登记到 | `backend/data/<project_id>/characters/characters.json` 的 `reference_images` |
| 一次运行的状态与断点 | `backend/data/runs/<run_id>.json` + 同名目录 |
| 工作流定义 | `backend/config/workflows/realistic-drama.json` |
| 六个写实模板 | `backend/config/prompts/scripts/real_*.yaml` |
| ComfyUI 口型预设 | `backend/config/comfyui_workflows/`（出厂为空，见 §5） |

## 2. 设计要点一：摄影规格只算一次，而且专门反磨皮

`style_bible`（②）产出的 `style_token` 是一段 **英文 40-70 词的完整摄影描述句**，
模板要求它覆盖且只覆盖这六项：

| 项 | 例子 |
|---|---|
| ① 拍摄媒介 | `shot on ARRI Alexa Mini, 35mm photochemical film` |
| ② 镜头与焦段 | `35mm anamorphic lens` / `85mm prime` |
| ③ 光圈与景深 | `T2.2 shallow depth of field` |
| ④ 布光方案 | `single source window key light, soft negative fill` |
| ⑤ 调色 | `muted teal-orange grade, lifted blacks` |
| ⑥ 质感 | `fine film grain, visible skin pores` |

④⑥⑧⑨ 四个生图节点的提示词开头都是同一句 `{{style_bible.style_token}}`，
负面词统一挂 `{{style_bible.negative_prompt}}`；分镜模板明确禁止分镜师自己再写
画风词或画质词。**两个风格源打架**在写实线上比动漫线更致命——一个模型收到
"cinematic film" 又收到 "8k ultra detailed"，出来的就是塑料人。

写实线的负面清单是模板里写死的，包含 `8k`、`ultra detailed`、`hyperrealistic`、
`perfect skin`、`smooth skin`、`HDR`、`airbrushed skin`、`plastic waxy skin`、
`3d render`、`extra fingers`、`text watermark` 等 12-20 项。理由就是那句核心判断：
**画质词在写实风里是负面资产**，越"完美"越像渲染。

质检（`real_qc_vision.yaml`）也和动漫线**反向**：动漫线怕油画味/水墨味/3D 味，
写实线怕的是磨皮塑料脸和 AI 假人，要求看见毛孔、看见单向光、看见瑕疵。
5 项各 0-2 分，第 1、2 项（皮肤质感 / 光影方向）任何一项为 0 分时总分不得超过 5，
⑧ 节点上 `threshold: 7`，不及格最多重生 2 次。

想换风格：只改 ② 一个节点。`/make` 页面「画风」那一栏（电影写实 / 手持纪实 / 霓虹夜色 /
室内暖调 / 悬疑冷调 / 年代戏）只是把意向送进 `{{style}}`，真正的六项由 ② 展开。

## 3. 设计要点二：定妆照自动回填档案库（这条线一致性最强的一环）

动漫线老版本的痛点是"定妆图只能给人看，吃不到后续镜头"。这条线补上了：
④ `character_assets` 上挂了

```json
"character_refs": true, "character_refs_max": 1,
"register_character": true, "register_character_max": 2
```

引擎在每次成功出图后（`_register_character`）会：

1. 按角色名在档案库里查人（`character_name_field` 没写就用 `name`）；
   项目在 `character_project` → 运行上下文 `project_id` → `"default"` 里依次取；
2. 把这一镜的 `image_prompt` / `appearance` / `costume` / `personality` 写进档案；
3. 把新生成的定妆图（最多 `register_character_max` 张）**追加**到 `reference_images`，
   同时**只替换本节点之前自动写入的那些路径**——你手动上传的图不会被冲掉。

于是 ⑧⑨ 的 `character_refs: true` 就真的能吃到定妆照：引擎按分镜里的角色名去档案库
捞参考图，挂进 `reference_images`。同框上限 `character_refs_max: 2`，超过两张脸一致性
会明显掉。

排错提示：如果日志里出现「定妆图登记跳过：…」，是档案库那边的问题（角色名对不上、
目录没权限等），不会中断出图。

## 4. 设计要点三：三个人三个嗓子，外加一句必须知道的铁律

⑩ `narration` 的配置：

```json
"engine": "edge",
"voice": "zh-CN-YunjianNeural",              // 兜底音色（查不到说话人时用它）
"voice_pool": [6 个 edge-tts 音色],           // 查不到但配了池子时按名字稳定分配
"voices_from": "character_generator",        // 从选角卡里读每个角色的 voice
"speaker_field": "speaker",                  // 分镜里哪一列是说话人
"text_field": "line"                          // 配音念的是纯台词
```

音色查找顺序（`_voice_table` + `_voice_for_speaker`）：

| 步骤 | 行为 |
|---|---|
| 1 | `voices_from` 指向的上游节点里，每个角色的 `voice_spec` 或 `voice` 建一张「角色名 → 音色」表 |
| 2 | 节点上手写的 `voice_map` **覆盖**表里的同名条目（可以在这里塞 GPT-SoVITS 克隆音色） |
| 3 | 说话人取 `speaker_field` 指定的列；没指定就扫 `speaker/character/role/who/说话人`；都没有时，**只有**当 `X：` 里的 X 是已知角色名才剥离前缀（所以"注意：下面这段…"不会被当成说话人） |
| 4 | 查不到精确名 → 子串模糊匹配 → `voice_pool` 稳定哈希分配 → 退回节点默认 `voice` |

`voice_map` 的值可以是字符串（`{"林晚": "zh-CN-XiaomengNeural"}`），也可以是完整规格：

```json
"voice_map": {"反派甲": {"engine": "gptsovits", "voice_name": "克隆_张三", "rate": "-5%"}}
```

也就是说**同一个配音节点里可以混 edge 和克隆音色**，谁在说话用谁的嗓子。

选角模板里的音色池是照抄 edge-tts 的真实 id 给的（女：Xiaoxiao / Xiaoyi / Xiaohan /
Xiaoqiu / Xiaomeng；男：Yunxi / Yunjian / Yunyang / Yunye / Yunfeng；方言：
liaoning-Xiaobei / shaanxi-Xiaoni），并且要求旁白用 Yunjian/Yunyang，
**不要占掉角色的音色**。

### ⚠️ 必须知道：配音是按**位置**对齐画面的

`final_cut` 把 `voices[i]` / `subs[i]` 按下标配到 `sources[i]` 上。这意味着
**只要有一镜没出音频，后面所有台词就会整体前移、贴到错误的画面上**。
所以 `real_storyboard.yaml` 第 12 条要求**每个镜头都必须有非空的 `line`**：
沉默戏不允许留空，改写成第一人称内心独白或旁白。这是刻意的约束，不是模板啰嗦。

### 台词与字幕是两轨

| 字段 | 内容 | 用途 |
|---|---|---|
| `line` | 纯台词，≤18 字，口型时长按它算 | ⑩ 配音 |
| `subtitle` | 「角色名：台词」12-24 字 | ⑬ 烧进画面 |

所以 ⑬ 上写的是 `subtitles_from: ["storyboard_generator"]` + `subtitle_field: "subtitle"`，
而 `voices_from: ["narration"]` 念的是 `line`。**成片字幕和配音内容不完全一致是设计如此**，
为的是短剧观众看字幕就知道谁在说话，而耳朵里听到的是干净的口语。

## 5. 口型同步（⑫ `lipsync`，出厂关闭）

关闭只有两个原因：要**本机装好 ComfyUI**，还要**有对应的预设文件**。

### 5.1 前置：分镜层面的口型四条件

`real_storyboard.yaml` 对对白镜头硬性要求：

1. 正面或 3/4 侧面，**嘴部不被遮挡**（不要捂着嘴、不要侧到只剩轮廓）；
2. 一镜只有**一个说话人**在画面里；
3. 近景或中近景（远景做口型等于浪费钱）；
4. 台词长度 ≤ 4 字/秒（5 秒镜头别塞 30 字）。

不满足这四条，模型再强也对不上。

### 5.2 接 ComfyUI 预设

引擎侧已经打通：`comfyui_video` 节点上的 `workflow_file` / `comfy_url` / `output_node`
现在会被真正转发给 ComfyUI provider（以前是静默丢弃），
`audio_from` 会按 foreach 下标把 ⑩ 的配音文件配对到同一镜，并作为 `audio_file`
上传进预设（`ComfyUIVideoProvider` 已支持）。音频文件不存在时发一条进度消息并
**跳过这一镜的口型**，不会把整条线搞挂。

预设**不要手写**，用导入脚本从你自己的 ComfyUI 生成：

```bash
cd ai-drama-studio/backend
# 在 ComfyUI 里把 InfiniteTalk 工作流跑通 → "Export (API)" → 存成 api.json
python scripts/make_comfyui_preset.py api.json \
  --name lipsync-infinite-talk \
  --output-node 42 \
  --map reference_image=12.image --map audio_file=15.audio --map width=8.width --map fps=8.frame_rate
```

脚本会：拒绝 UI 格式导出（`{"nodes": [...]}` 那种数组）并告诉该怎么重新导出；
校验 `--map` 里的节点号和字段名真实存在（不存在会列出该节点可用字段）；
提示哪些占位符会打断已有的连线；写出带 `{name, description, type, output_node,
nodes, params}` 外壳的预设；最后交叉检查预设里的占位符和引擎会喂的键对不对得上。
引擎每次一定会提供的键就这 11 个（`video_providers.py` 的 context）：

```
prompt / positive_prompt / negative_prompt / length / duration / seed
width / height / fps / reference_image / audio_file
```

`length` 是帧数（`fps × 秒`，Wan 的约定），`reference_image` 是该镜首帧，
**`audio_file` 是口型同步唯一的输入**——预设里没把它接到 LoadAudio 一类节点，
跑起来就是"有画面没对口型"，所以导入脚本专门会为它出警告。

### 5.3 打开并接上成片

⚠️ 只打开 ⑫ 是不够的：⑬ 的 `from` 出厂写的是 `["shot_videos"]`，
口型跑完了成片还在用旧的素镜。两句一起改，用 AI 助手最省事：

> 打开 realistic-drama 的 lipsync 节点，并把 final_cut 的 from 改成只用 lipsync 的产物

或者手改 JSON：`lipsync` 删掉 `"disabled": true`，`final_cut.from` 改成 `["lipsync"]`。

## 6. 怎么跑

### A. 一键成片页（推荐）

`/make` 顶部「① 用哪条流水线」选 **真人剧（写实电影感）**。这条线的表单和另两条有两处不同：

- 画风候选是**六项摄影规格的意向**（电影写实 / 手持纪实 / 霓虹夜色 / 室内暖调 / 悬疑冷调 / 年代戏）；
- 音色那一栏的标题变成「旁白 / 兜底音色」，并且下面写着：这条线按角色分音色，
  角色嗓子由 ③ 选角卡里每个角色的 `voice` 决定，想覆盖就在 AI 助手里改 `narration.voice_map`。

阶段列表会多出「定妆照（自动入库）」「分角色配音」「口型同步（默认关）」三项。
「先出 2 张候选关键帧」在写实线上尤其值——画风对不对，第 2 张图就能看出来。

### B. 流水线画布

`/pipeline` 选 `realistic-drama`，逐节点看参数与产物。注意右上角「运行」跑的是
**磁盘上的版本**，画布上没保存的改动不会生效。

### C. API

> 端口按你实际起的改：默认 8000，而本仓库 `frontend/.env.local` 把后端指到了 8013。

```bash
curl -X POST http://127.0.0.1:8000/api/runs/ -H "Content-Type: application/json" -d '{
  "workflow": "realistic-drama",
  "input": {"title":"体检报告被调包那天，儿媳一句没说把碗收了",
            "genre":"家庭悬疑","duration":"30 秒","style":"室内暖调，钨丝灯单一光源，胶片颗粒",
            "shots":6,"episodes":1},
  "overrides": {"shot_images": {"preview_gate": 2}}
}'
```

`input` 里的键就是模板里能扁平引用的键：`title genre duration style shots episodes voice`。
**其余一律写成 `{{节点id.字段}}`**，而且那个节点 id 必须在同节点的 `depends_on` 里
（`{{skin_texture_rule}}` 这种裸引用不会被解析，提示词里会留下原样的大括号）。

## 7. 用 AI 聊天改这条线

面板在 `/pipeline` 的「AI 助手」页签，所有改动都是**提案 → 你勾选 → 应用**，
不会偷偷写盘（细则见 `AI助手改步骤_使用说明书.md`）。这些句式在本条线的契约内：

| 你说 | 它会做 |
|---|---|
| 这个脸太假了，毛孔和皱纹再明显一点 | `prompt.patch` 收紧 `real_style` 的质感项与 `real_characters` 的"不完美的地方" |
| 别老给我大平光，全部改成单侧窗光 | patch `real_style` 的布光项 + ④⑥⑧⑨ 提示词里的布光子句 |
| 第二角色换个年轻一点的女声 | `workflow.node.patch` ⑩ `narration.voice_map` 加一条映射 |
| 这个反派要用我克隆的音色"张三" | ⑩ `voice_map.反派 = {engine:"gptsovits", voice_name:"张三"}` |
| 台词太书面了，全部改成口语短句 | `prompt.patch`：`real_script` / `real_storyboard` 的字句规则一起收紧 |
| 每镜 8 秒 | ⑪ `seconds` → 8，并提醒口型时长/台词字数上限要一起放宽 |
| 同框人太多脸会串 | ⑧⑨ `character_refs_max` → 1，并收紧分镜第「≤2 人」那条 |
| 质检太严老重生 | ⑧ `qc.threshold` 7 → 6 或 `max_attempts` → 1 |
| 分镜图先只出 2 张给我看 | ⑧ `preview_gate` → 2 |
| 打开口型同步，并让成片用口型后的视频 | ⑫ 删 `disabled` + ⑬ `from` → `["lipsync"]`（一次给你两个提案） |
| 打开尾帧，我要用 seedance 跑首尾帧 | ⑨ 删 `disabled` |
| 字幕里不要角色名，只留台词 | ⑬ `subtitle_field` → `line`（会提醒这样三个人说话就分不清谁是谁） |
| 把定妆照入库关掉，我自己管档案库 | ④ 删 `register_character` |
| 新建一条「年代戏」工作流，基于 realistic-drama | `workflow.create` |

## 8. 成本开关速查

| 开关 | 位置 | 默认 | 说明 |
|---|---|---|---|
| `preview_gate` | ⑧ / ⑨ | 无（一键成片页给 2） | 先出 N 张就停下等确认，最省钱的机制 |
| `qc.threshold` / `qc.max_attempts` | ⑧ | 7 / 2 | 写实线质检比动漫严，`max_attempts: 1` 能省一半 |
| `character_refs_max` | ⑧⑨ | 2 | 同框参考图上限，>2 掉得快 |
| `register_character_max` | ④ | 2（引擎缺省 3） | 每个角色留几张定妆照进档案库 |
| `concurrency` | ④⑥⑧⑨⑩ | 2 | 云端生图并发；尾帧/上一镜续接链自动降为 1 |
| `disabled` | ⑨⑫ | true | 尾帧、口型同步整节点关闭 |
| 角色 ≤3 / 场景 ≤2 / 每镜 5 秒 | 三个 llm 模板铁律里 | — | 写实线按张和按秒算钱，模板层面兜住 |

## 9. 排错

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 三个人还是一个嗓子 | ③ 选角卡没产出 `voice`，或 ⑦ 没填 `speaker` | 看 ③⑦ 的实际输出；临时用 ⑩ `voice_map` 写死；确认 `speaker_field: "speaker"` |
| **台词贴到错误的画面上** | 有镜头配音失败/`line` 为空（配音按位置配对） | 看 ⑩ 的产物数量是否等于镜头数；回分镜模板第 12 条，沉默戏必须有内心独白 |
| 皮肤还是塑料感 | 有人往提示词里加了画质词 | 确认只有 ② 产出风格词；把 `real_qc_vision` 第 1 条标准收紧 |
| 每张图光影都不一样 | ⑤ 实景卡的 `light_source` 没被逐镜复用，或 ② 布光项太泛 | patch `real_style` 布光子项写死单一光源方案 |
| 「定妆图登记跳过：…」 | 角色名和档案库对不上 / 项目 id 不对 | ④ 指定 `character_project`，或先建同名角色 |
| 打开 ⑫ 但成片没变化 | ⑬ 的 `from` 还是 `["shot_videos"]` | 改成 `["lipsync"]`（§5.3） |
| 报 `FileNotFoundError` 找不到预设 | `lipsync.workflow_file` 指向的 json 还没导出 | 用 `scripts/make_comfyui_preset.py` 生成（§5.2） |
| 口型没声音/没生效 | 预设里 `audio_file` 没接到占位符 | 导入脚本的交叉检查会警告；补 `--map audio_file=<节点>.<字段>` |
| 「⚠️ 配音音频不存在，本镜不做口型同步」 | ⑩ 该镜失败或文件被清理 | 正常降级行为；补齐配音后断点续跑该节点 |
| 提示词里出现原样的 `{{xxx}}` | 引用了非直接上游字段或节点配置里的键 | 挂 `depends_on`，或改成 `{{节点id.字段}}`；裸引用只在 foreach 的每一项字段里成立 |
| 成片有模糊边 | 生图与成片画幅比例不一致 | ⑥⑧⑨ 是 768x1344（9:16），⑫ 是 832x480，⑬ 输出 720x1280；改比例要一起改 |
| 自检报「不像 edge-tts 音色 id」 | 手写音色格式错 | 正确形如 `zh-CN-XiaoxiaoNeural` |

## 11. 三条线怎么选

| | 真人短剧 `drama-pro` | 真人剧（写实） `realistic-drama` | AI 动漫 `anime-drama` |
|---|---|---|---|
| 节点数 | 8 | **13** | 12 |
| 定位 | 快速出条，能发就行 | 像真人拍的 | 像一部番 |
| 画风来源 | `plot.yaml` 的 `visual_style` | 独立 ② 摄影规格节点，四个生图节点强制拼接 | 独立 ② 画风圣经 |
| 定妆照 | 无 | 有，**且自动入库当参考图** | 有，只给人看 |
| 配音 | 单音色 | **按说话人分音色**，可混克隆 | 单音色 |
| 口型同步 | 无 | `lipsync` 节点（默认关，需 ComfyUI） | 无 |
| 质检取向 | 通用 | **反磨皮/反塑料**（与动漫反向） | 怕真人质感/3D 味 |
| 夸张来源 | 微表情 | 表演微动作 + 机位微动 + 正反打节奏 | 机位 + 漫画符号 |
| 单镜成本 | 低 | **高**（多两道资产链 + 严质检） | 中高 |
| 适合 | 追热点、日更 | 品牌感、悬疑/家庭情绪戏 | 玄幻、异能、热血 |

**先跑哪条**：只想验证引擎通不通，用 `drama-pro`；要"看不出是 AI"，用这条但
预算按 1.5-2 倍准备；题材本身是架空的，去动漫线——写实线会把不合理的东西照出原形。

> 仓库里还有第四条 `standard-drama`（10 节点，带分集与"角色/场景资产只生成一次全剧复用"），
> 它是这三条之前的老多集结构，`/make` 页面不列它，也不在这次改造范围内。

## 12. 已知限制（诚实清单）

1. **⑫ 口型同步没有"逐镜开关"**：节点一旦启用就对每一镜跑，包括空镜和反应镜头。
   正确做法是让分镜只给对白镜留说话人，或复制一条工作流按镜头筛（目前要手工）。
2. **`lipsync-infinite-talk.json` 出厂不存在**，必须你自己从 ComfyUI 导出（§5.2）。
   没有它时 ⑫ 保持关闭，`test_workflows.py` 只会警告不会失败。
3. **打开 ⑫ 要同时改 ⑬ 的 `from`**，否则成片照旧（§5.3）。引擎不做这个耦合，
   因为替你改配置文件的耦合更容易造成困惑。
4. **只有 ComfyUI 通道吃 `audio`**：`seedance` / `agnes` / `zhipu` 收到配音字段会忽略，
   不会报错。想做口型只有本机 ComfyUI 这一条路。
5. **动漫线仍是单音色**：分镜模板没有 `speaker` 列，所以那边吃不到新能力。
   想要的话说一句「给 anime-drama 的分镜加 speaker 并让配音按角色分音色」，
   要改的是模板 + ⑩ 的配置，引擎不用动。
6. **本条线未做真机端到端验证**：这台机器上后端依赖（`openai`、`python-dotenv`、
   `python-multipart`）装不全，六个模板的实际 LLM 输出质量、定妆照入库后的跨镜脸稳度、
   以及口型同步的实际效果都还没跑通过。上面所有断言来自代码与静态自检，
   自检覆盖的是"配置层面会不会炸"，不是"画面好不好看"。第一次跑请用 `preview_gate: 2`。
7. **沉默戏也要有台词文本**（§4 的位置对齐机制），这意味着纯氛围镜头会被塞一句内心独白，
   不想要就在 ⑬ 用 `subtitles_from` 换成别的来源，或让那一镜的旁白极短。
